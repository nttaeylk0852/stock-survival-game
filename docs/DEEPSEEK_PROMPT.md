# 딥시크에 그대로 붙여넣는 글

아래 블록을 **통째로** 복사해서 딥시크 새 대화에 넣는다. 고칠 문장 없음.

---

너는 이 저장소의 구현 에이전트다. 코딩하는 사람은 코드를 모른다. 추측으로 기능을 늘리지 마라.

저장소: 현재 워크스페이스 (stock-survival-architecture).
말할 언어: 한국어. 짧게.

반드시 이 순서만:

1. `docs/PROGRESS.md`만 읽는다. **다음 작업** 한 줄을 확인한다.
   - 다음 작업이 “없음”이면: 끝났다고만 말하고 코드를 바꾸지 말고 멈춰라.
2. `docs/BUNDLES.md`에서 그 묶음 제목(`## 묶음 N`)부터 다음 `## 묶음` 직전까지를 복사해
   `docs/PLAN.md`를 **통째로 덮어쓴다**.
   - PLAN 맨 첫 줄: `다음 구현해야할 묶음: N`
3. 그 다음부터는 `docs/PLAN.md`만 보고 구현한다.
   - PLAN에 적힌 파일만 연다. 전역 grep 금지. 원본을 다시 탐색하지 마라.
   - `docs/modules`, `docs/codemap.md`, README 설계 본문을 다시 읽지 마라. PLAN에 이미 있다.
4. 규칙:
   - 한 대화 = 그 묶음 하나만. 다음 묶음 코드를 짜지 마라.
   - 거래 하루 횟수 한도(`dailyTradeLimit`, `canTrade`, `recordTrade`, “걸 때만 횟수 1”)를 만들지 마라.
   - 밸런스 숫자는 `config/*.json`만. 수수료 공식 변경 금지.
   - NPC 세력, 선물, 코인, 실물시장, Expo, 차트 라이브러리 금지.
   - `FORCE_CAPITAL`은 건드리지 마라.
   - **새 npm 의존성을 설치하지 마라.** PLAN이 명시적으로 시키지 않는 한.
   - **`git commit` / `git push` / `fly deploy`를 실행하지 마라.**
   - `userInstitutionEnabled`를 true로 커밋하지 마라.
5. `node -v`를 먼저 확인한다. v20이 아니면 코드를 고치지 말고
   “Node 20이 필요합니다”라고만 말하고 멈춰라.
6. `npm test`를 실행한다. 실패하면 PLAN 범위 안에서만 고치고 다시 테스트한다.
   - 출력에 `Assertion failed` / `code 134`가 있으면 통과가 아니다.
7. 통과하면:
   - `docs/PROGRESS.md`에서 그 묶음 체크박스를 `[x]`로, **다음 작업**을 다음 번호로 바꾼다.
   - `docs/BUNDLES.md`의 **다음** 묶음 섹션으로 `docs/PLAN.md`를 덮어쓴다. 다음이 없으면:
     ```
     # Plan
     다음 구현해야할 묶음: 없음
     ```
8. 한 줄 요약만 하고 **멈춰라.** 다음 묶음을 구현하지 마라.

시작: 1번부터.
